# حاسب التشطيب — Tashteeb Tracker

تطبيق ويب عربي بالكامل (RTL) لتتبع وإدارة مصاريف تشطيب الشقة، مع قراءة الفواتير
بالذكاء الاصطناعي، ومقارنة الأسعار بالسوق، ومساعد محادثة يعرف بيانات مشروعك.

## المزايا

| الميزة | الوصف |
| --- | --- |
| تسجيل يدوي | اسم البند، التصنيف، سعر الوحدة، الكمية، الوحدة، التاريخ، المورد، الملاحظات |
| قراءة الفواتير (OCR) | رفع صورة فاتورة → استخراج البنود والأسعار والكميات والتاريخ تلقائياً |
| توزيع الخصم | الفاتورة التي تخصم من الإجمالي تُسجَّل بنودها بالسعر الفعلي المدفوع لا السعر الكامل |
| كشف التكرار الذكي | يمنع تسجيل نفس البند مرتين (نفس الفاتورة، أو بند مسجّل سابقاً) |
| بنود قابلة للتوسعة | ١٠ بنود تشطيب جاهزة + إضافة/تعديل/حذف بنود مخصصة |
| بحث شامل | داخل البنود والملاحظات والموردين والنص المستخرج من الفواتير |
| مقارنة بالسوق | تقييم أسعارك مقابل متوسطات السوق المحلي مع نصائح توفير |
| المساعد الذكي | محادثة عن الجدول الزمني والتكاليف والبدائل والإرشاد الفني |
| لوحة تحكم | إجماليات، رسوم دائرية وأعمدة، المخطط مقابل الفعلي، المصروف الشهري |
| أرشيف الفواتير | معرض لكل الصور المرفوعة مع البنود المرتبطة بكل فاتورة |
| يعمل بدون إنترنت | تطبيق PWA قابل للتثبيت — كل شيء يعمل بلا اتصال عدا المزايا الذكية |
| مزامنة بين الأجهزة | حساب واحد يجمع بياناتك وصور فواتيرك على الموبايل واللابتوب (اختيارية) |

## التشغيل

```bash
npm install
npm run dev
```

ثم افتح `http://localhost:5173`.

للبناء للإنتاج:

```bash
npm run build && npm run preview
```

## تفعيل الذكاء الاصطناعي

مزايا الذكاء الاصطناعي (قراءة الفواتير، مقارنة السوق، المساعد) تحتاج مفتاح
**Gemini API** مجاني من [Google AI Studio](https://aistudio.google.com/app/apikey):

> إذا أظهر زر «جلب المتاح» نموذجاً واحداً فقط، فغالباً المفتاح مقيّد أو المشروع
> المرتبط به جديد. جرّب: تفعيل **Generative Language API** في مشروع Google Cloud
> المرتبط بالمفتاح، أو إنشاء مفتاح جديد من AI Studio في مشروع آخر، أو تفعيل
> الفوترة (الطبقة المجانية حصتها أضيق وتظهر فيها أخطاء 503 أكثر).

1. افتح صفحة **الإعدادات** داخل التطبيق.
2. الصق المفتاح في حقل «مفتاح Gemini API».
3. اضغط **جلب المتاح** لعرض النماذج المسموح بها لحسابك، ثم **اختبار الاتصال** للتأكد.

النموذج الافتراضي `gemini-3.6-flash`. أسماء نماذج Google تتغيّر ويُوقَف دعم القديم
منها، لذا حقل النموذج حرّ الكتابة وبجانبه زر يقرأ النماذج المتاحة فعلياً من حسابك
(`ListModels`) — فلا يتعطّل التطبيق عند تغيّر الأسماء مستقبلاً. النماذج القديمة
المحفوظة (`gemini-1.x` / `gemini-2.x`) تُحدَّث تلقائياً إلى الافتراضي عند التشغيل.

المفتاح يُحفظ في `localStorage` على جهاز المستخدم فقط ويُرسل مباشرة إلى Google،
ولا يمر على أي خادم وسيط. باقي مزايا التطبيق (التسجيل اليدوي، التقارير، الرسوم)
تعمل بدون مفتاح.

> ملاحظة: بما أن الطلبات تُرسل من المتصفح، فالمفتاح مكشوف لمن يفتح أدوات المطوّر
> على نفس الجهاز. للنشر العام لعدة مستخدمين، انقل نداءات `src/lib/ai.ts` إلى دالة
> خادمية (Serverless Function) واحتفظ بالمفتاح في متغيرات البيئة.

## العمل بدون إنترنت (PWA)

التطبيق يعمل بالكامل بدون اتصال بعد أول فتح:

- **ما يعمل بدون إنترنت:** تسجيل المصاريف وتعديلها وحذفها، البحث والتصفية، لوحة
  التحكم والرسوم البيانية، البنود والميزانيات، أرشيف الفواتير وصورها، تصدير CSV
  والنسخ الاحتياطية.
- **ما يحتاج اتصالاً:** قراءة الفواتير بالذكاء الاصطناعي، مقارنة الأسعار بالسوق،
  والمساعد الذكي. هذه تظهر رسالة فورية توضّح ذلك بدل محاولات فاشلة.

### التثبيت على الجهاز

| المنصة | الخطوات |
| --- | --- |
| Android / Chrome | القائمة ⋮ ← «تثبيت التطبيق» أو «إضافة إلى الشاشة الرئيسية» |
| iPhone / Safari | زر المشاركة ← «إضافة إلى الشاشة الرئيسية» |
| سطح المكتب | أيقونة التثبيت في شريط العنوان |

التثبيت يفتح التطبيق بملء الشاشة بدون شريط المتصفح، **ويقلّل كثيراً من احتمال حذف
المتصفح لبياناتك تلقائياً** — وهو أهم سبب عملي للتثبيت.

### التحديثات

عند رفع نسخة جديدة يظهر شريط علوي «تتوفّر نسخة محدَّثة» مع زر **تحديث الآن**.
التحديث لا يُفرض تلقائياً حتى لا تُعاد تحميل الصفحة أثناء إدخال بيانات.
يتحقق التطبيق من وجود تحديث كل ساعة.

> ملاحظة تقنية: عامل الخدمة (Service Worker) لا يعمل في وضع التطوير (`npm run dev`)
> حتى لا يخزّن نسخاً قديمة أثناء العمل. لتجربته محلياً: `npm run build && npm run preview`.
> ويتطلب التشغيل عبر HTTPS (أو localhost) — وهو متوفر تلقائياً على Netlify/Vercel/Cloudflare.

## التعامل مع أخطاء الخدمة

يتعامل التطبيق مع ازدحام خوادم Google على ثلاث مراحل تلقائية:

1. **إعادة محاولة** على النموذج نفسه حتى ٣ مرات بتباعد متزايد (١ ثم ١٫٨ ثم ٣٫٢ ثانية
   تقريباً مع تشويش عشوائي).
2. **تحويل تلقائي لنموذج بديل**: لو استمر الازدحام، يقرأ التطبيق النماذج المتاحة
   لمفتاحك ويجرّب حتى ٣ بدائل مرتّبة من الأخف (`flash-lite` ← `flash` ← `pro`) لأن
   الأخف عادةً الأقل ازدحاماً. عند نجاح بديل يُحفظ في الإعدادات ويظهر تنبيه يخبرك
   بالتحويل — فالطلبات التالية تذهب إليه مباشرة.
   لو كان الحساب لا يتيح سوى نموذج واحد، يُجري التطبيق ٣ محاولات إضافية عليه
   (٧ محاولات إجمالاً) بدل الاستسلام.

أثناء الانتظار يظهر مؤشر «إعادة المحاولة ٣/٤ بعد ٢ ثانية…» في المحادثة وفي شاشة
قراءة الفاتورة، حتى لا يبدو التطبيق متجمّداً.
3. **رسالة عربية + زر «إعادة المحاولة»** داخل المحادثة لو فشل كل ذلك.

حالات أخرى: **404** (نموذج غير موجود) يُعامَل كعابر فيُجرَّب البديل تلقائياً،
و**400/403** (مفتاح غير صالح) تعطي رسالة صريحة بمراجعة المفتاح دون محاولات ضائعة.

## المزامنة بين الأجهزة (اختيارية)

بدون تفعيلها يعمل التطبيق محلياً بالكامل: بيانات كل جهاز منفصلة عن غيره — وهذا
يشمل التطبيق المثبّت على iPhone، فهو يعمل في حاوية تخزين منفصلة عن سفاري.

### الإعداد لمرة واحدة

1. أنشئ مشروعاً مجانياً على [Supabase](https://supabase.com/dashboard).
2. من **SQL Editor** شغّل محتوى الملف [`supabase/schema.sql`](supabase/schema.sql)
   — يُنشئ الجدول وسياسات الأمان وحاوية الصور.
3. من **Project Settings ← API** انسخ **Project URL** و **anon public key**.
   (الرابط بالشكل `https://xxxx.supabase.co` — وليس رابط لوحة التحكم. التطبيق
   يصحّح الأشكال الشائعة تلقائياً ويعرض الرابط الفعّال بالأخضر.)
4. **مهم:** من **Authentication ← URL Configuration** اضبط `Site URL` وأضف نفس
   العنوان في `Redirect URLs`. بدونها يعود رابط تأكيد البريد إلى
   `localhost:3000` الافتراضي فتظهر صفحة فارغة. التطبيق يعرض العنوان المطلوب
   جاهزاً للنسخ داخل شاشة المزامنة.
5. في التطبيق: **الإعدادات ← المزامنة بين الأجهزة** → الصق القيمتين.
6. أنشئ حساباً بالبريد وكلمة المرور، ثم سجّل الدخول بـ**نفس الحساب** على كل جهاز.

> لتبسيط الاستخدام الشخصي يمكن تعطيل تأكيد البريد من:
> Authentication ← Sign In / Providers ← Email ← عطّل **Confirm email**.

### كيف تعمل

- **المحلي أولاً**: كل كتابة تحدث على الجهاز فوراً، والمزامنة تجري في الخلفية.
  التطبيق لا يتوقف أبداً في انتظار الشبكة.
- **مزامنة تلقائية** بعد ٨ ثوانٍ من آخر تعديل، وعند فتح التطبيق، وعند عودة الاتصال.
- **حل التعارض**: عند تعديل نفس البند على جهازين، تفوز النسخة الأحدث (`updatedAt`).
- **مؤشران منفصلان**: السحب يعتمد على وقت **الخادم** (`syncCursor`)، والرفع على وقت
  **الجهاز** (`lastPushAt`). خلطهما يُضيع تغييرات الجهاز صاحب الساعة المتأخرة:
  لو كانت ساعة الموبايل متقدمة، يبدو كل ما يسجّله اللابتوب بعدها «أقدم» من آخر
  مزامنة فلا يصل أبداً. لذلك يضبط trigger في قاعدة البيانات `updated_at` بوقت
  الخادم دائماً ويتجاهل ما يرسله العميل.
- **مزامنة كاملة**: زر في شاشة المزامنة يتجاهل المؤشرات ويعيد مطابقة كل البيانات
  — للاسترجاع لو تباعدت الأجهزة لأي سبب.
- **الحذف ينتقل** عبر شواهد حذف (tombstones) تُنظَّف تلقائياً بعد ٣٠ يوماً.
- **صور الفواتير** تُرفع إلى Supabase Storage وتُنزَّل على الأجهزة الأخرى عند الحاجة.

### الإعدادات المشتركة

اسم المشروع والعملة والميزانية الكلية والمنطقة تُزامَن بين الأجهزة، لكن **فقط عند
تغييرها فعلاً**: لكل تعديل طابع زمني (`settingsUpdatedAt`) يُرفع معه، ولا يُقبل من
الخادم إلا ما كان أحدث من النسخة المحلية.

رفعها في كل مزامنة — كما كان سابقاً — يجعل آخر جهاز يضغط «مزامنة» يكتب نسخته فوق
تعديل الجهاز الآخر فيمحوه، حتى لو لم يلمس الإعدادات أصلاً.

### ما لا يُزامَن عمداً

مفتاح Gemini، اسم النموذج، السمة (فاتح/داكن)، وبيانات مشروع Supabase نفسه —
تبقى على كل جهاز. كذلك سجل المحادثة وتحليلات السوق تبقى محلية.

### الأمان

المفتاح العام (anon) مصمَّم ليكون داخل المتصفح، والحماية من **سياسات RLS**:
كل صف مرتبط بـ `user_id`، ولا يستطيع أي حساب قراءة أو تعديل بيانات حساب آخر.
صور الفواتير محفوظة في مسار `<user_id>/` بسياسات مماثلة.

## الخصومات على الفواتير

كثير من فواتير الموردين تعرض سعر كل صنف كاملاً ثم تخصم من الإجمالي. بدون معالجة،
تُسجَّل البنود أغلى من المدفوع فعلياً وتتضخّم تقارير المصاريف.

- **خصم لكل بند (الحالة الشائعة)**: كثير من الموردين يخصمون على أصناف بعينها
  دون غيرها، ويكتبون النتيجة في عمود «الإجمالي» آخر السطر. لذلك يقرأ التطبيق هذا
  العمود كما هو ويشتق منه سعر الوحدة الفعلي، بدل حساب (العدد × السعر) الذي يتجاهل
  الخصم. البنود بلا خصم تبقى بسعرها الكامل. كل سطر يعرض سعره الفعلي وبجانبه
  السعر المعلن مشطوباً.
- **خصم إجمالي على الفاتورة كلها**: إن لم تحمل البنود خصمها، ولم يطابق إجمالي
  الفاتورة مجموع البنود، يظهر خيار توزيع الفرق على البنود بالتناسب.
- **تحذير «المتبقي»**: «متبقي» أو «باقي» في الفاتورة **دَين لم يُسدَّد**، وليس خصماً.
  التطبيق لا ينقصه من التكلفة — فالبضاعة استُلمت بكامل قيمتها.
- **لفاتورة أُضيفت سابقاً**: افتحها من أرشيف الفواتير ← **توزيع خصم** ← أدخل المبلغ
  المدفوع فعلياً. تُحدَّث أسعار بنودها بالتناسب فوراً.
- يُحفظ السعر قبل الخصم في `listUnitCost` فيظل ظاهراً للمراجعة، ويُستخدم السعر
  بعد الخصم في كل الحسابات والتقارير.

التوزيع تناسبي: `معامل = المدفوع ÷ مجموع البنود`، ويُقرَّب لقرشين لكل بند.

## تخزين البيانات

- **بيانات التطبيق** (المصاريف، البنود، المحادثات، الإعدادات) في `localStorage`.
- **صور الفواتير** تُحفظ **كبايتات** (`ArrayBuffer`) لا ككائن `File`. تخزين `File`
  مباشرة يحفظ إشارة إلى ملف في نظام التشغيل، وعلى iOS يُفرَّغ هذا الملف بعد إعادة
  تشغيل التطبيق فتصبح الصورة بحجم صفر ويفشل رفعها بـ «No content provided».
- **صور الفواتير** في `IndexedDB` بعد ضغطها تلقائياً — لتجنّب امتلاء `localStorage`.
- **نسخ احتياطي**: من الإعدادات يمكن تصدير/استيراد ملف JSON يحتوي كل شيء.

لا يوجد خادم ولا حساب مستخدم — كل البيانات على جهاز المستخدم.

## كيف يعمل كشف التكرار

1. **بصمة البند** = الاسم بعد التطبيع العربي (إزالة التشكيل، توحيد `أإآ→ا` و`ة→ه`
   و`ى→ي`) + التاريخ + السعر + الكمية. تطابق البصمة = تكرار مؤكد.
2. **تشابه تقريبي**: نفس التاريخ + فرق سعر ≤ ٢٪ + تشابه اسم ≥ ٠٫٨٢ (مسافة
   ليفنشتاين) = تكرار محتمل.
3. **داخل الفاتورة الواحدة**: السطور المتطابقة تُوسم وتُستبعد من التحديد.
4. **صورة الفاتورة**: بصمة SHA-256 تكشف رفع نفس الصورة مرة أخرى.

البنود المشتبه بها لا تُحذف — تظهر بلون تحذيري وغير محدّدة، ويبقى القرار للمستخدم.
